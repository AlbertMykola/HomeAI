# Full-app simulator QA

Figma source: [Rehomely · A / Flows](https://www.figma.com/design/W5U3Q7e9HY5WCcnpqEu6fd/Rehomely?node-id=6-7254). Current reference frames and their motion/dev notes were read for all 12 sections. Paywall `131:7252` is current; `27:7255` is explicitly the old version.

## Reproducible catalog

`HomeAIFullQA` builds the app, hosted UIKit checks and UI tests. `AppQA` is DEBUG-only; Release cannot enable fixture mode. The catalog uses the actual controllers and storyboard scenes, native sheets and their detents. It currently contains 72 screens/states across onboarding, tabs, wizard, tools, generation, results/editors, assistant, projects, profile, paywalls and errors.

Launch examples:

```text
--app-qa --qa-screen home --qa-language uk --qa-home-focus interior
--app-qa --qa-screen paint --qa-language de
--app-qa --qa-screen wizard-final --qa-generation-fail
--app-qa --qa-screen compare --qa-reduce-motion
--app-qa --qa-screen wizard-final --qa-premium --qa-generation-delay 3
--app-qa --qa-screen wizard-final --qa-generation-failure server --qa-generation-fail-once
```

Set `REHOMELY_FULL_QA=1` in the hosted test process. `FullAppSnapshotTests` accepts:

| Environment | Meaning |
| --- | --- |
| `REHOMELY_QA_LANGUAGES` | Comma-separated locale codes; default all 15 shipped languages |
| `REHOMELY_QA_SCREENS` | Optional subset of `AppQA.screens` |
| `REHOMELY_QA_SNAPSHOTS=1` | Save full-resolution PNGs |
| `REHOMELY_QA_APPEARANCES` | Comma-separated `light,dark`; both are independent report combinations |
| `REHOMELY_QA_SNAPSHOT_LANGUAGES` | Capture selected locales; every requested locale is still inspected and failures always save PNGs |
| `REHOMELY_QA_STRICT_LABELS=1` | Check single-line static/control labels, minimum font scale and labels extending beyond their controls; dynamic cell titles and partially visible carousel peers are excluded |
| `REHOMELY_QA_SCROLL_CONTENT=1` | Inspect static vertical content at overlapping scroll positions, bounded multiline copy and non-scroll controls outside the viewport; report includes `scrollPositions` |
| `REHOMELY_QA_USED_FREE` | Optional used-free allowance count (0, 1, 2), restored after the test |

Results live in the simulator app's `Library/Application Support/FullAppQA`: screenshots per locale, `layout-report.json`, `analytics.jsonl`, local image/project/assistant fixtures. The fixture credit count uses memory instead of Keychain; history and assistant conversations use their own folder, saved ideas their own defaults key. Supabase image upload is disabled for fixtures.

`tools/qa/run_matrix.py` runs two simulators at a time by default, archives their results and shuts them down. Each device has a cross-process lease through shutdown. It cooperates through `/private/tmp/rehomely-simulator-boot.lock` so simultaneous QA jobs can reserve simulator capacity. Waiting workers retain admission order to prevent starvation; Booting devices also consume capacity. `--priority <UDID> ...` selects early devices; `--jobs` and `--max-booted` control workers and shared capacity. Pass a frozen Xcode Products folder containing `RehomelyMatrix.xctestrun`; this keeps an ongoing run independent of later builds.

A completed device's `result.json` is reused when resuming the same output folder. Use a new output folder after source or manifest changes. For a focused repair, retain the earlier evidence until the affected cases pass again, then report the latest result for each device/language/screen/appearance. Do not count duplicate reruns as additional unique coverage. Archived screenshot folders can contain older failure captures; only captures produced by the current snapshot run show its current appearance.

Create the catalog manifest from the `.xctestrun` generated by `build-for-testing` (after freezing/copying Products):

```sh
python3 tools/qa/prepare_xctestrun.py --source /absolute/Products/HomeAIFullQA_iphonesimulator27.1-arm64.xctestrun --output /absolute/Products/RehomelyMatrix.xctestrun --snapshots
python3 tools/qa/run_matrix.py --devices /absolute/devices.json --products /absolute/Products --output /absolute/results
```

Use `xcrun simctl list devices available -j` to create `devices.json`. `prepare_xctestrun.py` also accepts `--screens home,paywall`, `--languages uk,de` and `--scroll-content`. Scrolled captures carry an offset in each issue; dynamic collection/table cells and zoomable image canvases are excluded from static scrolling. Separate UI/SDK jobs must finish on a device before another installation on that device.

`tools/qa/audit_catalog_images.py --output /absolute/catalog.json` checks bundled enum/curated assets first, then public remote HEAD availability with the production folder-to-basename fallback. It does not verify image content or decode every file.

## Layers of verification

1. `tools/qa/audit_localization.py`: valid `.strings`, missing English-reference keys, duplicate keys, positional format arguments, literal Swift/XIB localization references. Dynamic sample copy in XIBs is not a translation key; the controller sets its localized value.
2. `FullAppSnapshotTests`: actual window geometry, visible label height, selected header fitting, nontruncated paywall copy, sheet existence, screenshots. Entrance animations are settled for this catalog. Ellipsis in user/project titles remains allowed; the report is not a universal visual-equality test.
3. `FullAppBehaviorTests`: visible onboarding page analytics, correlated generation success/failure/retry/cancellation, credit gate and accounting, interrupted entrance under Reduce Motion. A local provider drives the production generation runner and persistence pipeline.
4. `FullAppFlowTests`: taps and gestures through Home → wizard → generation → Result → Paint → new version → share, tabs/project/language, error retry and background/resume. `OnboardingUITests` also launches every shipped language through native `AppleLanguages`, without the localization-bundle override.
5. `FullAppMotionTests`: normal/reduced motion, settled entrances and repeat appearance for all 72 catalog states. This runs with real animation timing, separately from screenshots. `REHOMELY_QA_MOTION_SCREENS` selects an affected subset for a focused repeat.
6. `StoreKitLifecycleTests`: local native StoreKit trial/purchase/finish/restore/expiration/cancellation. This is separate from Adapty's server entitlement verification. [Apple's testing documentation](https://developer.apple.com/documentation/storekit/testing-in-app-purchases-in-xcode) describes the local environment.
7. `LiveOnboardingSDKTests`, enabled only by `REHOMELY_LIVE_SDK_QA=1`: normal SDK startup, ATT after O4, paywall. `LiveBackendSmokeTests`, enabled by `REHOMELY_LIVE_BACKEND_QA=1`: one real image request using a bundled room photo and the configured production provider; does not persist a fixture generation as a real user design.
8. `InspirationDetailTransitionTests`: opens Detail from a real feed card using the production custom transition, samples panel geometry/opacity throughout presentation, checks settled bounds, safe-area CTA visibility, dismissal and source-card restoration with normal/Reduce Motion. A separate method checks the full CTA text in all 15 languages and both themes. `FullAppFlowTests/testInspirationDetailCanBeOpenedClosedAndTried` covers native repeated card taps, close and Try routing. These checks catch transition movement that a settled catalog snapshot cannot detect.
9. `PresentationCopyRegressionTests`: Profile preparation before the first visible frame, initial scroll callbacks and reentry; full Profile/Tips copy in all languages/themes; scroll access to Tips CTA; Generate duration across all tools and free/Pro states. For a focused layout-only rerun after an unrelated caption change, `REHOMELY_QA_SKIP_GENERATION_COPY=1` omits the already-verified Generate matrix and records zero generation checks. `FullAppFlowTests/testProfileTipsAndDurationCorrections` exercises Profile return, real Tips open/close and duration-only Reference CTA. Detail motion also checks corner radius/masked corners and photo layers covering the panel, supplemented by simulator video.
10. `LocalGenerationFlowTests` and `LocalGenerationFlowUITests`: use bundled outputs through the real runner/history/Projects pipeline; all 11 options, restored Reference/mask edits, duplicate taps, edits/versions/deletion, portrait/landscape/square/small responses, free/Pro export/HD/Story composition, errors/retry/cancellation, actual Compare clipping/drag/zoom/Fit geometry, native compare/share/collapse and cold reopening of the saved project. Reports and exported image samples go to `FullAppQA/local-generations`. `tools/qa/run_matrix.py --test <target/suite>` accepts repeated test selections.

## Local generation development

Run the shared **HomeAILocalGenerationQA** scheme in Xcode to explore the complete app with local image responses (Ukrainian, dark theme, fixture Pro, 3-second delay). It uses the existing `--app-qa` adapters, a separate history directory, in-memory free/daily quotas and a local analytics journal. Normal HomeAI and Release builds keep the configured production provider.

`QAGenerationService` maps tools to bundled photos. Exterior/Garden use bundled card-sized photos; floor-plan uses a raster placeholder. These fixtures test presentation and persistence, not model quality, architectural accuracy or server response decoding. Portrait/landscape/square/small-response tests resize a bundled photo locally to exercise layout bounds.

QA startup skips third-party SDK initialization. `QANetworkBlocker` intercepts HTTP in shared URLSession and is explicitly included in all app-created generation/upload session configurations; upload scheduling is disabled. A guard test intentionally attempts an `.invalid` host through shared/ephemeral sessions and requires both requests to be intercepted locally. Other generation tests require zero unexpected HTTP attempts. The legacy `-fakeGeneration` shortcut is not used, because it bypasses parts of the real accounting/analytics pipeline.

Saved Reference generations now retain `reference.jpg`; Replace/Remove retain a lossless `mask.png`. Their optional relative metadata paths remain compatible with older history. Mask regeneration reloads the matching edit input from that version's `original.jpg`, rather than applying a saved mask to the project's initial photo.

Story preview uses the same 9:16 composition as export and hides the underlying split preview. Pro's HD toggle controls the export resolution. Share content scrolls below its fixed title on compact screens; multiline option rows expand with their localized text. `testShareSheetActionsRemainReachableAcrossLanguages` checks all 15 languages in Free/Pro and scrolls the primary Share button fully into view.

The native collapse step uses `--qa-reduce-motion` to avoid XCTest waiting for the continuous scan animation before sending its tap. The main generation/compare/edit/export flow uses normal animations. A native Duo investigation found window bounds466×678 with a right safe-area inset84pt: earlier layouts had placed controls underneath the simulator's clock/Wi-Fi panel. Controller horizontal anchors, reference-layout widths, onboarding pager and floating Share respect the usable horizontal viewport. The current tab bar is UIKit's native bar; UIKit supplies its content safe area and adaptive placement. Native Compare Fit and banner Close use normal centre taps; safe-area overlap is checked by the scroll/layout audit.

## Analytics boundaries

Simulator/DEBUG builds intentionally opt out of Amplitude and Firebase. The local journal verifies event names, parameters, sequence and duplication; it does not prove server delivery. Legacy chat/prompt events now contain lengths rather than user text. The connected Amplitude workspace lists `HomeDesignAI`; its mapping to this app must be confirmed before querying that project's data.

Run native StoreKit sessions sequentially for reproducibility, separately from catalog/UI runs. The fixture explicitly sets `en_US` / `USA`, finishes verified transaction updates and polls expiration. Keep failed results until investigating and completing the run. Motion checks verify settled visibility/reentry with the shared DS override; native Accessibility Settings toggling and hardware haptics are outside that assertion.

## Compact localized copy control sweep

`DSAdaptiveChipRow` keeps finite chip pairs horizontal when their natural text and icon widths fit, otherwise stacks them. It measures text directly and is updated by the owning controller, rather than calling Auto Layout fitting recursively from its own `layoutSubviews`. Authored chip margins do not inherit changing safe-area margins. Long feedback/custom-style content scrolls above `keyboardLayoutGuide`.

Photo-source text, rearrangement explanations, Share action captions, premium perks and notification previews can wrap. Generation failure content scrolls above the fixed retry/change-photo actions. Welcome/summary/short action labels use a bounded minimum font scale where keeping one line is appropriate. Current hierarchies and constraints live in `HomeAI/Storyboards`; `tools/xibgen/specs` is an archived source of the superseded XIB implementation and must not regenerate current screens.

The `result-ask` and `result-ask-pro` catalog states expose the open Ask panel without focusing the keyboard. Its input and Send control are checked against the window safe area. Result's Ask panel stays open when an external keyboard produces a zero keyboard overlap while the text view remains first responder. Dismissal explicitly closes the panel even without a keyboard-frame notification. Native checks type a wrapping paragraph, drag vertically inside the panel to close, reopen, and then open Share. A directional pan supports deliberate slow drags; text selection and controls retain their own touches. Return remains the send action.

Focused allowance fixtures use `--app-qa --qa-used-free 1` for the last-free banner. Its Close is a sibling of the large pressable banner, so the pressable control cannot disable or swallow the Close button's touch. `ControlInteractionUITests` exercises this dismissal and returning to Home.

The completed-run section above records configuration coverage and repairs. Static image catalog HTTP checks are separate from offline generation/HTTP-guard checks; an unavailable remote fetch is not proof of a broken bundled image.

Home quick-edit captions and Plan titles/subtitles wrap; Plan cards keep a minimum height and grow with translated copy. The focused control sweep explicitly inspects these cards after scrolling, rather than only auditing the initial viewport.

Editing/Restyle/feedback retry actions also display `action · About30s` in both Free and Pro; accounting and quota gates still execute in the runner. `PresentationCopyRegressionTests/testEditingActionsShowDurationForFreeAndPro` checks360 combinations including both free-retry availability states. Editor and retry labels can wrap inside their buttons.


## Storyboard checks

`python3 tools/qa/audit_storyboards.py` validates scene IDs, local IB references, named colors, typed factory mappings and cell prototype identifiers. `StoryboardLayoutTests` checks native tab items, UIKit safe-area reservation and hiding/restoration through navigation. `OnboardingLayoutTests` checks child page origins, viewport width and height through pager transitions and resize. The pager owns child frames and disables their decoded autoresizing masks, so the initial storyboard scroll-view size cannot stretch or overlap pages. `FigmaVisualParityTests` also resizes the Result version strip and requires all fixture thumbnails to remain inside it.

## Adaptive layout and first-generation review

`StoryboardLayoutTests` verifies Home heights/fonts through synthetic phone → large iPad → landscape-size window → phone, paywall viewport fill, collapsed Pro restore group, all tool guidance in every shipped language, bundled vector floor-plan decoding and sufficient thumbnail pixels for the rendered Projects card. The app retains its existing iPad portrait lock; the synthetic landscape window is a resize check, not native device rotation. `PresentationCopyRegressionTests/testAssistantAndProjectsAreHiddenBeforeTheirFirstEntranceAndDoNotReplay` checks the pre-appearance state plus normal/Reduce Motion and reentry. `ControlInteractionUITests` covers real Home routes, per-tool tips, selecting a bundled plan and generating a local result, a single-tap Compare action and the actual StoreKit rating interface. Custom-style examples begin their entrance before keyboard activation so the keyboard cannot interrupt their initial visibility.

First-generation review state is isolated in the QA preferences suite. `--qa-system-review --qa-reset-review` enables a fresh native StoreKit prompt during the QA flow; ordinary fixtures record the request locally without presenting it. `FullAppBehaviorTests/testFirstGeneratedResultRequestsRatingOnceAcrossRelaunch` verifies that history, unrelated results, reopening and further generations cannot consume a second request. StoreKit controls actual production display: [Apple documentation](https://developer.apple.com/documentation/storekit/appstore/requestreview(in:)-1q8qs).

Paywall content fills the scroll viewport with a preferred equal height so its illustration yields space to copy on phones and grows on tablets. The payment timeline uses the preceding row's bottom rather than a fixed offset; the due-today price group moves below its caption when their natural widths do not fit. Guidance and the affected service messages use storyboard-authored minimum heights measured after their own final label bounds arrive.
